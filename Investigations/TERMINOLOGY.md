# TERMINOLOGY — the verdict vocabulary of this codebase

*Instituted 2026-07-26 on Harvey's cascade-repair directive: "change the language choices, in
regards to 'kill' etc. I want congruence, consistency and accuracy or their opposites."
This document governs all live protocols, registers, and future verdicts. It supersedes the
kill/graveyard/blade vocabulary everywhere the vocabulary is operative.*

---

## The three axes — every verdict names its axis

A claim is judged on three orthogonal axes, each with its opposite:

| axis | positive | negative | what it tests |
|---|---|---|---|
| **Accuracy** | **ACCURATE** | **INACCURATE** | the claim's *number* against the measured anchor |
| **Consistency** | **CONSISTENT** | **INCONSISTENT** | the claim against the framework's own laws and other earned results — no internal contradiction |
| **Congruence** | **CONGRUENT** | **INCONGRUENT** | the claim's *mechanism/structure* against the phenomenon's structure — the shape fits |

A complete verdict states all three where testable: a result can be ACCURATE but INCONGRUENT
(right number, wrong mechanism), or CONGRUENT but INACCURATE (right shape, magnitude off), or
ACCURATE and CONGRUENT but INCONSISTENT (contradicts another earned result — a cascade flag).
**A refutation must name WHICH axis failed.** "Refuted" without an axis is not a verdict.

## Origin labels (unchanged — already ruled, 2026-07-25)

These sit beside the axes and are not replaced by them:
- **CONVERGENT** — same number as a rival, from an independent SDT theoretical origin (meaningful).
- **DEGENERATE** — same number with no independent origin (shared input / relabelling only).
- **DERIVED / CALIBRATED / OBSERVED / IDENTITY / PENDING / OPEN** — provenance labels, as before.

## Legacy → current mapping (for reading historical files)

| legacy term | reads as |
|---|---|
| KILL / KILLED | REFUTED on the named axis — **INACCURATE** (number failed), **INCONSISTENT** (self-contradiction), or **INCONGRUENT** (structure refuted); the re-adjudication register carries the per-item axis |
| KILL-CONFIRMED | refutation re-verified — INACCURACY (or named axis) CONFIRMED |
| KILL-OVERTURNED | refutation reversed — the claim returns to OPEN or earns its axis positives |
| kill-gate / blade | **accuracy gate** — a pre-committed threshold whose failure = INACCURATE |
| graveyard | the **refuted register** (claims with a confirmed negative-axis verdict) |
| strike-force / wave | historical batch-run names — proper nouns, kept in dated records |
| FISHED / FISHED-RECOVERY | unchanged — a knob dressed as a result (fraud label, not an axis) |
| GATE-CONTRABAND | unchanged — a gate enforcing a rival's axiom (procedure label, not an axis) |

## Record-preservation rule (why history is not rewritten)

Dated verdict files, run logs, and register *entries* are **evidence**. Rewriting their words
retroactively falsifies the record of what was decided and when. Therefore:
1. **Live controlling documents** (protocols, methods, templates, the register's rules) carry the
   new vocabulary in full.
2. **Historical dated records** keep their original text; this file is the single mapping by which
   they are read. No mass find-and-replace across dated records.
3. **New work** (verdicts, registers, prompts, commit messages) uses the axis vocabulary from now on.

## Usage in prose

Plain verbs are fine — "refuted", "fails the gate", "survives" — but the **verdict line** of any
investigation must carry the axis words. The violent register (kill, dead, execute, autopsy,
graveyard, blade) is retired from operative use.

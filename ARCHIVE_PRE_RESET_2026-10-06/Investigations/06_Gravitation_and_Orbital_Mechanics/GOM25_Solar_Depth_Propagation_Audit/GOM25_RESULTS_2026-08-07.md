## 2. Inputs, mechanism, and initial conditions

The tested implemented chain is:

```text
koppa = v_orbit² r_orbit / c²
z(r)  = koppa / r
z_spec = z(R_Sun) - z(r_observer)
c_far = c (1-z)²
```

No solar mass, `G`, precomputed solar koppa, or reference-framework timing
formula enters the GOM25 prediction path.  The orbital state comes from the
frozen JPL vector table; the spectral comparator comes from the frozen
HARPS-LFC CDS tables.

### Pre-registration correction

The first version of the decision rule used only `c*koppa/R_Sun`, while the
mechanism stated a depth *differential*.  This would have omitted the
observer-depth term by about 3 m/s.  Amendment 01 corrected the value to
`c*koppa*(1/R_Sun - 1/r_observer)` before any GOM25 numerical calculation.
This is a specification repair, not an empirical adjustment.

### Observed initial-condition failure

Across all 27 Earth-Moon-barycenter states, the constructed koppa has:

```text
mean = 1477.262359762 m
sample SD = 18.010233553 m
coefficient of variation = 1.219163%
```

Thus `v² r` is not constant along the observed trajectory.  The implemented
law `v = c sqrt(koppa/r)` is a circular-orbit relation when `koppa` denotes one
constant body property, but the code and current claim wording do not state
that initial condition or provide a non-circular extension.  The data do not
license treating the row average as a general orbital invariant.

**Standing:** `UNADJUDICATED`.  This is a mechanism/domain defect, not a
rejection based on another gravitational framework.  To become testable, SDT
must either (a) state and use a measured circular-orbit initial condition, or
(b) derive a non-circular equation that predicts the observed vector sequence
without fitting koppa after observation.

## 4. Exact far-frame profile audit

For the prior GOM22 formal geometry (`r1 = 1 AU`, `r2 = 1.524 AU`,
`b = 695,700 km`) and the D1 mean koppa, the one-way excess-propagation delay
was numerically integrated from the adopted profile:

```text
integrand = 1 / [c(1-koppa/r)^2] - 1/c
```

| Calculation | One-way excess delay |
|---|---:|
| Simpson 4,096 intervals | 123.675398862 microseconds |
| Simpson 16,384 intervals | 123.675398863 microseconds |
| Simpson 65,536 intervals | 123.675398862 microseconds |
| engine `shapiro_delay()` leading-order formula | 123.675376690 microseconds |
| finite-path leading-order integral | 123.675300463 microseconds |

The exact profile differs from the engine leading-order helper by `+0.022172`
nanoseconds on this formal geometry.  This is numerically small in the solar
regime, but the distinction is mathematical, not optional.

**Formal finding F1:** the statement that `c_far = c(1-z)^2` and
`shapiro_delay()` are exactly the same calculation is false.  Error origin:
the helper retains a leading-order logarithmic expression while the adopted
profile includes higher powers and the finite path has endpoint corrections.

**Attempted repair:** none is applied to canonical code.  A valid proposal
would label the helper `leading_order`, add a domain-checked quadrature for
precision work, and require a new out-of-sample timing test.  The present
helper may remain useful as an approximation only under that label.

## 5. Inverse-domain audit

The adopted forward profile is non-injective outside its stated physical
domain: `c_far(z=2) = c_far(z=0) = c`.  The current inverse consequently
returns 0 when supplied the forward value at `z=2`, rather than recovering 2.

**Formal finding F2:** `depth_from_c_far()` is not a global inverse.  Error
origin: the principal square root silently selects the `0 <= z <= 1` branch
without guarding the input domain.

**Attempted repair:** none is applied to canonical code.  A proposal must
reject `z >= 1` and document the physical scope of the far-frame profile;
otherwise strong-field or cosmological extrapolations can silently use an
ambiguous inverse.

## 6. Prior Shapiro evidence correction and raw-data gate

GOM22 reports a 247.24 microsecond value as measured, but its source code
constructs that target as:

```text
dt_measured = (4 * (GM_Sun/c²) / c) * log(4*r1*r2/b²)
```

That is a model-loaded calculation, not an ingested timing observation.

**Formal finding F3:** the prior GOM22 numerical comparison cannot support an
empirical claim about a Shapiro-like marker.  Error origin: the same solar
length and propagation form under test are used to manufacture the comparison
target.

**Corrective action completed:** a primary Cassini Solar Conjunction
Experiment tracking-data sample, PDS label, archive index, and provenance
record are frozen in `Datasets/solar_propagation_2026-08/raw/`.  The label's
`64,820` records of `288` bytes exactly match the 18,668,160-byte TDF.

**Standing:** `PENDING_RECONSTRUCTION` for the claimed external-frame timing
marker, not a pass or a failure.  The archive is publicly available, but a valid test
still needs full conjunction coverage, a tested PDS decoder, station clock and
frequency-ramp calibration, solar-plasma treatment, and independently
recomputed line-of-sight geometry.  No delay amplitude, profile exponent, or
solar koppa may be fitted after inspecting that residual.

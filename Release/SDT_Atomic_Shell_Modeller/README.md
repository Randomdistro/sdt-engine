# SDT Atomic Lobe-Tour Modeller

Run locally with:

```powershell
.\serve-atomic-shell-modeller.ps1
```

Open `http://127.0.0.1:8766/Release/SDT_Atomic_Shell_Modeller/index.html`.

## Inputs and initial conditions

- `ATOMICUS/tools/_iaea_ground_states.csv` is filtered to its non-zero local abundance field (`288` entries in the supplied extract). It supplies isotope identifiers, `A`, `Z`, abundance, half-life, and decay fields; it is not used as evidence for module positions. Its lithium composition values conflict with NIST's representative terrestrial values, so `6Li = 7.59(4)%` and `7Li = 92.41(4)%` are explicitly overridden and labelled as NIST values in the UI.
- `data/nist-neutral-ground-state-configurations.json` provides local curated neutral-occupation records where present. The repository's occupation sequence fills the remaining elements so every natural isotope can render. These labels select angular starting geometry only; they are not SDT dynamics.
- The Atomicus alpha/deuteron/triton count rule is applied only from `Z >= 3`, as declared in `docs/atomicus-nuclear-model.html`. The light bases are explicit: `1H` proton, `2H` deuteron, `3H` triton, `3He` helion mirror, and `4He` alpha. They are not labelled grammar failures.
- `6Li` is rendered as an alpha core with a face-capping deuteron; `7Li` as an alpha core with a face-capping triton. For other in-scope nuclei, the displayed order is alpha core, then deuterons, then tritons using the repository's canonical shell-coordinate assignment.
- Lithium is an isotope control, not confirmation of an electronic mechanism: both neutral isotopes use `1s2 2s` as the occupation input; measured nuclear spin and magnetic moment differ (`6Li: I=1, mu=+0.822056`; `7Li: I=3/2, mu=+3.25644`, in nuclear magnetons). A model must predict a calibrated observable before attributing a difference to a valence-electron drive.
- Canonical `s`, `p`, `d`, and `f` lobe forms provide angular/nodal tour geometry only. A standard probability lobe has no finite outer edge without selecting an arbitrary isovalue, so this code does not use a quantum radial-density calculation or an isovalue cutoff.
- `data/nist-codata-2022-hydrogen-boundary.json` records the NIST/CODATA 2022 `alpha`, `a0`, classical electron radius, and light-nucleus rms charge radii used here. NIST states the hydrogenic reference relation `alpha = v1/c`; the app therefore calculates `k_H = c/v_H` and `K_H = a0/k_H^2`. The computed hydrogen-only value is checked against the NIST/CODATA classical electron radius (`2.8179403205 fm`). Other elements do not reuse it.
- `data/iaea-livechart-natural-charge-radii-2026-08-28.json` is a local, SHA-256-labelled extraction of IAEA LiveChart's ground-state `radius` field for the natural-isotope catalogue. It supplies a positive experimental rms charge radius for `285` of `288` entries; current NIST/CODATA values override the archived IAEA values for `1H`, `2H`, and `4He`. `33S`, `50V`, and `231Pa` are excluded because IAEA encodes their unavailable radius as zero. No value is derived or imputed.
- The selected rms charge radius is an experimentally inferred moment of the charge distribution, not a measured hard nuclear edge. To honor the requested nuclear-radius constraint without inventing a density-profile conversion, the renderer treats that value as an explicit packing-envelope cap: it scales packing centres only downward when the constructed nucleon/D-T envelope would exceed it, and rejects any component that cannot fit. This is a display constraint, not a claim that the rms radius is a physical surface or that the resulting module coordinates are experimentally measured.
- `1H` uses the NIST/CODATA proton rms charge radius `0.84075 fm`, which rounds to the requested `0.84 fm` and lies inside hydrogen's electron-scale boundary. Every isotope's constrained envelope is separately compared with its selected element boundary; an overrun is recorded as a falsification finding.
- Every paired marker carries engagement `2`: a `1s` pair retains its existing pi-locked polar relation, while a post-`1s` pair also receives conjugate `+/-30 degree` ellipse planes. Every `n > 1` carrier follows a focus-centred ovoid orbit with the selected element boundary at one focus and one marked closest-approach side. Every tour is sampled against that boundary and rejected if it crosses.
- The packing supplies a visual initial axis for the `1s` and lobe basis. Light symmetric bases retain the positive `z` axis; lithium uses the face-cap normal; larger nuclei use a principal axis of the canonical coordinates. This is a construction choice, not a measured molecular or atomic orientation.
- For neutral lithium and beryllium only, the `2s` tour axis is displayed perpendicular to that `1s` reference axis. Beryllium's measured `2s2` occupation starts as an opposed, same-sense pair; lithium retains its measured single `2s` carrier. This is declared visual geometry, not an observed directional electron arrangement or an additional force.
- Carbon's `1s2` carriers are rendered on two great-ellipse planes that share the packing-derived polar axis and cross at its poles. Lithium retains one post-`1s` oval; beryllium uses two maximin antipodal apoapses and begins with matched apoapsis phase. Because the app renders one atom at a time, this is a common local-frame convention, not a measured inter-element co-rotation.
- The supplied Atomic Shape Cycle remains a declared lobe-frame input layered on the standard `s`/`p`/`d`/`f` angular envelopes. It does not determine the post-`1s` core-orbit apoapses: after every carrier addition the app recomputes all post-`1s` apogee directions to maximise their minimum angular separation. Counts two through six use exact antipodal, triangular, tetrahedral, triangular-bipyramidal, and octahedral layouts; larger sets use deterministic numerical relaxation. Thus boron has a three-way `120 degree` apoapsis layout, carbon has a four-way tetrahedral apoapsis layout, and beryllium has two diametrically opposed apoapses. No nonphysical wireframe guide is rendered, and none of these placements is a measured directional resistance, probability density, or force law.
- When an alpha module is present, the renderer can expose its four-nucleon contact tetrahedron and one poloidal reference loop. The loop is a packing diagnostic, not a nucleon orbit, trajectory, or force term. Its contact-volume number uses the declared `internalRadius * protonBoundary` scale proxy and is not a measured nuclear density distribution.
- Deuteron and triton modules retain the `(2,3)` centreline path at `2R_wake,p = 1.6828 fm`. Law IV supplies `V_disp,e` and `V_disp,p`; the electron back-filter uses `L=2 pi a0` and `b_e=sqrt(V_disp,e/(pi L))`, while the proton volume tube uses `b_p=sqrt(V_disp,p/(2 pi² R_wake,p))`. These widths describe the displaced-volume construction, are exaggerated visually, and are never used as exclusion or wake radii.

## SDT-only dynamic model

- For each selected element the app uses the circular convention `k=c/v` and `K=r_atom/k²`. Hydrogen therefore gives `v=alpha c`, `k=1/alpha`, and `K=alpha²a0=2.8179403204 fm=r_e=r_S/2`. The superseded `sqrt(2)` branch calculated `r_S` while labelling it `r_S/2`.
- `data/nist-neutral-excitation-map.json` supplies 20 NIST evaluated resolved bound states and the first-ionization limit for H through Ne. Blank-term multiplet centroids are excluded. The map computes `E_b=E_limit-E_n`, circular-equivalent `v=sqrt(2E_b/m_e)`, `k=c/v`, and `r=Kk²`. The hydrogen ladder returns approximately `k_n=n/alpha`; the common recoil-scale residual remains displayed rather than being hidden by redefining K.
- Measurement audit: nuclear rms charge radii are distribution measurements, not hard surfaces, and no loaded experiment measures a turning point at `K`. Electron-capture decay and finite-nuclear-size spectroscopy require a quantitative coupling mechanism; a strict claim of zero electronic support/coupling inside `K` is therefore not supported by the measurements and conflicts with them unless SDT reproduces those observables by another mechanism.
- Electron taxonomy: `R_excl` is actual displaced volume; `R_wake` describes rapidly circulating displaced spations and is neither a material surface nor a containment radius; `K_H=r_e` is the hydrogen c-boundary scale; `R_quantum` is reduced Compton coherence. Geometric containment uses only the declared physical matter/contact boundary. Displacement cascades through surrounding shells to establish pressure against matter, while wake rotation has no direct optical-blocking role absent coherent polarising flux.
- Direct electron-electron body occlusion uses `R_excl,e = 2.877579e-21 m`. The geometric-mean charge radius remains a Coulomb-normalisation construction and is not used as a literal femtometre-scale electron collision area.
- At every update, the model projects the existing `F_occlusion` result onto the tour tangent and integrates `domega/dt = F_tangent / (m ds/dphi)`; directional forces and solid angles otherwise use the engine's `F_occlusion` and `Omega = pi R^2/r^2` contracts. The rigid structure rotation remains the torque response of those same forces.
- The view-clock conversion is presented separately from physical quantities. It changes only how quickly femtosecond/attosecond-scale motion is rendered; it is not an extra force, fit parameter, or hidden physical coefficient.
- The display-time slider has discrete rates from `0.001x` (1000x slower) to `2x`. It multiplies only that presentation conversion. The volume ledger exposes the existing algebraic scaling: under a uniform nuclear-radius change at fixed separation, the model's `Omega` and `F_occlusion` radius-squared factors scale as `V^(2/3)`. The displacement relation remains `z = kappa/r`; it has no nuclear-volume term in this implementation.
- Video-style controls provide explicit play and pause actions, previous/next isotope steps, and double-arrow previous/next occupation-closure jumps. A closure jump navigates to the closest available neutral `Z = 2, 10, 18, 36, 54, or 86` catalogue entry; it changes no equation or simulated state beyond selecting that entry's declared inputs.

## Required audit

`Engine/include/sdt/laws.hpp` declares the atomic seat `r_atom = a0 n^2/Z`. The app now combines that selected-element radius with `k=c/v_valence` to obtain `K=r_atom/k^2`; it displays the resulting closure ratio directly. It separately exposes packing cases that exceed the selected element boundary rather than silently reverting to hydrogen's `2.8179403205 fm` value.

No observed electron trajectory, finite lobe edge, spectral residual, many-electron density comparison, or nuclear module-coordinate dataset is included. The app is therefore a transparent model instrument, not an atomic validation claim.
